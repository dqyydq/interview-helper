# 题目发现与来源可追溯导入设计规格

> 产品：Interview Helper
> 状态：用户已确认产品方向，等待规格审阅
> 日期：2026-07-23
> 范围：本地优先 MVP 的“发现题目”扩展，不改变现有手动题库工作流

## 1. 背景与已确认的产品决策

现有题库可以由用户手动新增、编辑、筛选和检索，但不能帮助用户从公开资料中发现适合特定公司、面试轮次、岗位和能力方向的题目。对于准备不同公司、不同轮次的用户，这会把大量时间耗在资料搜集、去重、整理和判断来源可信度上。

本功能不把“网上搜到的内容”直接当作正式面试题，而是新增一个受用户控制的发现与审核流程：

1. 保留现有本地题库搜索和手动加题，二者始终可离线使用。
2. 在知识库中增加独立的“发现题目”工作区，用于公开网页搜索和粘贴链接导入。
3. 搜索结果先进入带来源证据的候选池，而不是直接进入面试计划。
4. 用户选择题库、检查或编辑后，才会导入为草稿题；只有用户显式激活的题目才能被面试计划使用。
5. 面试风格、公司、轮次和岗位是检索与整理的条件，不代表系统声称存在官方、统一或永久有效的招聘标准。

默认体验面向中文互联网中的面经与技术社区资料。产品提供受控的全网开关、域名白名单和黑名单，但不会做站点级爬虫、批量搬运或无确认自动入库。

## 2. 目标与非目标

### 2.1 目标

- 帮用户更快地发现与“公司 + 轮次 + 岗位 + 技能方向”相匹配的公开题目线索。
- 支持两条来源路径：
  - 可配置的搜索服务连接器；
  - 用户粘贴 1–5 个网页链接，由系统提取可处理的公开内容。
- 用专门的 Researcher 模型角色把有边界的来源片段整理为可审阅的题目候选。
- 为每个候选和导入后的题目保留最小必要的来源证据、时间和可信度说明。
- 让现有题库、规划器和模拟面试只消费用户已确认、已激活的本地题目。
- 将外部搜索密钥与 LLM 模型连接分离管理，并以加密形式保存。

### 2.2 非目标

- 不构建公共共享题库、题目社区、题目交易或跨用户内容推荐。
- 不宣称任何内容是公司官方题库、官方评分规则或真实面试必然发生的题目。
- 不抓取整个站点、绕过登录/付费墙/robots 限制，或长期保存完整网页正文。
- 不让发现结果自动影响简历、记忆、历史面试评价或下一场面试计划。
- 不在本期做语义向量检索、全网实时监控、自动关注站点或自动持续同步。
- 不替代用户对题目质量、来源许可和适用性的最终判断。

## 3. 信息架构与用户旅程

知识库保持一个清晰的三级任务边界：

| 工作区 | 用户意图 | 数据状态 | 是否进入面试计划 |
| --- | --- | --- | --- |
| 题库 | 管理自己的正式题目 | 草稿或已激活题目 | 仅已激活题目 |
| 发现题目 | 搜索、阅读证据、筛选候选 | 临时候选与来源记录 | 否 |
| 简历 | 管理专项面试上下文 | 简历与结构化片段 | 间接用于计划个性化 |

“发现题目”作为知识库下的独立路由 /questions/discover，而不是顶级导航或题库页里的临时弹窗。桌面端沿用产品当前的“精密控制台”语言：清晰网格、克制的黑白信息层级、单一高亮色、证据可展开但不喧宾夺主；移动端将标签缩短为“发现”。

~~~mermaid
flowchart LR
    A["输入目标<br/>公司 / 轮次 / 岗位 / 技能"] --> B{"发现方式"}
    B --> C["公开网页搜索<br/>默认中文资料域预设"]
    B --> D["粘贴 1–5 个链接"]
    C --> E["连接器返回受限结果/片段"]
    D --> E
    E --> F["安全检查与来源规范化"]
    F --> G["Researcher 结构化整理"]
    G --> H["候选池：题目 + 证据 + 去重提示"]
    H --> I["用户选择题库并编辑"]
    I --> J["导入为 DRAFT 题目"]
    J --> K["用户显式激活"]
    K --> L["规划器可选用"]
~~~

用户完成一次发现的最短路径：

1. 在“发现题目”输入公司、轮次、岗位、技能标签；可选题型和难度。
2. 选择“搜索公开资料”或“导入链接”；默认启用中文面经 / 技术社区的域名预设。
3. 浏览候选卡，查看题干、匹配理由、建议标签、来源、抓取时间、证据摘录与重复风险。
4. 选中一个或多个候选，指定本地目标题库；在导入预览中可修改任何题干、标签、难度和适用范围。
5. 导入后题目默认为 DRAFT；用户在题库审核并激活后，规划器才会将它纳入模拟面试。

## 4. 搜索范围与来源策略

### 4.1 默认策略

- 默认选择“中文面经与技术社区”来源预设；预设是可版本化的域名集合和策略说明，而非对网站内容的背书。
- 搜索条件只包含用户在发现表单中显式输入的公司、轮次、岗位、技能、题型、难度和关键词。
- 未开启“全网搜索”时，连接器仅请求预设允许的域名。
- 用户可以在高级筛选中增加域名白名单和黑名单；黑名单优先，且用户规则不能覆盖系统的安全禁止名单。
- 开启“全网搜索”需要显式开关确认，界面持续显示“结果可能包含来源不明或低相关内容”的提示。

### 4.2 链接导入策略

- 用户一次最多提交 5 个 HTTP(S) 链接。
- MVP 通过已配置搜索连接器的 Extract 能力处理链接，不在应用服务器上直接抓取任意网页。应用只允许调用由服务端固定配置的连接器端点；用户不能提交自定义搜索端点、代理地址或回调地址。
- 在交给连接器前，应用对 URL 做规范化与策略校验：只允许 HTTPS（HTTP 仅在本地开发明确启用时允许）、拒绝凭据、非默认端口、localhost、IP 字面量、单标签主机、保留 / 非公网地址和不符合白黑名单的域名。域名比较采用规范化后的精确域或带点边界的子域匹配，不能用简单字符串后缀匹配。
- 应用会用受信任解析器检查输入主机的 A / AAAA 记录；任一解析结果不属于可公开路由地址即拒绝。此检查降低明显风险，但不能声称替代 Extract 供应商内部的 DNS、跳转或网络隔离保护。
- 重定向与正文抓取发生在第三方 Extract 供应商一侧，因此其 SSRF 防护是一个明确的受信任边界，而不是应用服务器可完全验证的事实。只有经过安全评估、能承诺阻止内网目标并提供规范化最终 URL（或明确不跟随不透明跳转）的连接器才能启用链接导入；不满足该契约的连接器只能用于关键词搜索。
- 连接器适配器对收到的响应仍执行本地限制：允许的文本类结果、最大响应体、每源规范化文本长度、超时和来源数量均受下文的硬上限约束。供应商不返回可验证的安全元数据时，界面不得把其内容标记为“已验证来源”。
- 单个来源失败不会导致整次发现失败；失败项显示原因并允许用户移除或修改链接。
- 受密码保护、登录后内容、付费内容、不可访问内容和超出内容大小限制的页面不做绕过或重试抓取。

第一版内置 Tavily 适配器，并抽象为可替换的 SearchProvider 接口。Tavily 的官方 Search 与 Extract 文档说明了受控搜索、域名包含 / 排除和 URL 提取的能力，适合作为这一受限 MVP 的初始实现：[Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search) 与 [Extract API](https://docs.tavily.com/documentation/api-reference/endpoint/extract)。后续可以添加 Brave、Serper 或自建检索服务，而不改变候选池、导入和审计边界。

## 5. 可信度、风格与题目适用性

公司和轮次“风格”不是单一标签或模型臆测，而是有来源、有不确定性的结构化建议：

- 每条来源都标记为“官方材料”“公开经验分享”“技术社区讨论”或“未知 / 待判断”。
- 默认把面经和社区内容视为二手经验；候选卡和导入后的来源记录都必须显示这一点。
- Researcher 只能基于候选来源中可见的证据提取题目及可能的考察方向，不能把来源中的主观结论升级为事实。
- 公司、轮次、岗位和能力标签均可多选，并标记为“建议”；用户可在导入时修改。
- 对应的面试风格包仍由产品中的公司 / 轮次配置管理。题目发现可以为风格包提供候选证据，但不能自动覆盖既有风格配置。

候选卡的最小可见信息：

- 题干或可编辑的题目草案；
- 匹配理由，以及匹配的公司、轮次、岗位、技能；
- 建议题型、难度与标签；
- 来源标题、规范化 URL、来源类别、抓取时间；
- 有长度上限的证据摘录；
- 置信度与“非官方 / 二手经验”提示；
- 与本地题库已有题目的精确重复或相似题提示。

## 6. 数据模型与状态机

本功能在现有 Question / QuestionBank 模型之外增加面向“发现过程”和“来源追溯”的实体。最终字段命名可随现有 SQLAlchemy 约定微调，但职责边界不得改变。

### 6.1 连接器配置

DiscoveryConnector（按 profile 隔离）：

- provider_type，例如 tavily；
- 显示名称、启用状态、能力声明、非敏感配置；
- 加密后的 API 密钥或凭据引用；
- 最近连接测试、健康状态和错误摘要；
- 创建 / 更新 / 最后使用时间。

密钥绝不返回给前端、绝不写入日志、绝不与 ModelConnection 共用表或配置入口。连接器诊断页只显示连接是否可用、配额或错误类别，不显示原始响应。

### 6.2 发现过程

QuestionDiscoveryRun：

- profile_id、发起者、创建时间；
- source_mode：SEARCH 或 URLS；
- 结构化查询快照（公司、轮次、岗位、标签、题型、难度、关键词、域策略）；
- 使用的 connector 和配置版本；
- 状态、阶段、进度、部分成功统计、错误代码与可安全显示的错误摘要；
- 取消时间、完成时间、数据保留到期时间。

QuestionDiscoverySource：

- profile_id、run_id、原始 URL（仅在必要时短期保留）、规范化 URL、最终允许的 URL；
- 标题、域名、来源类别、抓取时间、内容哈希；
- 获取状态：PENDING、FETCHED、BLOCKED、FAILED；
- 有长度上限的来源摘录和归因信息；
- 安全检查、策略命中和失败原因。

QuestionDiscoveryCandidate：

- profile_id、run_id、结构化题目草案、建议标签、适用公司 / 轮次、题型、难度；
- 匹配理由、置信度、整理模型、schema 版本和用于导入的乐观锁 revision；
- 规范化内容哈希、相似本地题目 ID 列表；
- 状态：PROPOSED、SELECTED、REJECTED、DUPLICATE、IMPORTED、FAILED；
- 导入计数；具体导入结果只记录在 Import 记录中。

QuestionDiscoveryCandidateEvidence：

- profile_id、candidate_id、source_id；
- 与该候选直接相关的短证据摘录、来源定位信息和置信度。

QuestionDiscoveryImport：

- profile_id、candidate_id（临时关联，清理后可为空）、candidate_content_hash、目标 bank_id、创建后的 question_id；
- 导入请求的 idempotency_key、请求内容哈希、候选版本和创建时间；
- 导入状态、失败摘要和批次 ID；
- 每个 profile + candidate + bank 只有一条成功导入记录，避免同一候选在同一题库生成重复草稿。

导入时创建不可变内容、可单独删除的 QuestionSourceProvenance：

- profile_id、question_id、来源标题、规范化 URL、域名、来源类别、获取时间；
- 短证据摘录、发现运行 ID（可空的历史引用）、候选 ID（可空的历史引用）；
- 仅保留支持题目可追溯所需的最小信息。

导入后的 Question 使用现有 SourceType.LINK_IMPORT，默认状态为 DRAFT。用户仍可通过现有“手动新增”创建 SourceType.MANUAL 的题目；两条路径彼此独立。

所有发现实体都显式带有 profile_id，而非仅通过 run 间接归属。服务层对任何读取、取消、去重、证据关联和导入都先按 profile 过滤；写入时还必须验证 candidate、source、run 属于同一 profile 和同一次运行，且目标 QuestionBank 属于当前 profile。数据库使用复合唯一约束 / 外键或等价事务校验防止跨运行关联；绝不把仅凭 UUID 命中的记录视为已授权。

### 6.3 去重与幂等性

1. 先用规范化题干哈希识别精确重复。
2. 再用受限的文本相似度检索候选本地题目，返回少量可人工比较的结果。
3. 系统不自动合并、不自动覆盖、不自动修改已有题目。
4. 同一候选向同一题库重复导入时返回既有 Import 结果，避免生成多份相同草稿。
5. 第一阶段不支持把发现结果直接写为 QuestionVariant：现有 Variant 尚无来源追溯和差异说明模型。用户可“查看已有题”“编辑后作为独立新题导入”或“放弃导入”；若编辑后仍命中同一规范化哈希，服务端拒绝创建。
6. 后续若提供“导入为变体”，必须先扩展 Variant 的来源追溯、差异说明、导入幂等和审核模型，不能借由普通 Variant 接口绕过本规格。

### 6.4 生命周期

~~~mermaid
stateDiagram-v2
    [*] --> QUEUED
    QUEUED --> RUNNING
    RUNNING --> SUCCEEDED: 有候选且无可见失败
    RUNNING --> PARTIAL: 有候选且存在来源/整理失败
    RUNNING --> NO_RESULTS: 正常完成但无可审阅候选
    RUNNING --> FAILED: 无可用输出且发生不可恢复错误
    QUEUED --> CANCEL_REQUESTED
    RUNNING --> CANCEL_REQUESTED
    CANCEL_REQUESTED --> CANCELLED
    SUCCEEDED --> [*]
    PARTIAL --> [*]
    NO_RESULTS --> [*]
    FAILED --> [*]
    CANCELLED --> [*]
~~~

RUNNING 内部阶段为 SEARCHING、EXTRACTING、CURATING，只用于进度呈现，不作为终态。PARTIAL 是保留部分结果的终态，不能在后台静默改写为 SUCCEEDED；NO_RESULTS 是可解释的正常终态，而非 FAILED。

取消使用原子状态转换：API 仅能把 QUEUED 或 RUNNING 更新为 CANCEL_REQUESTED。Worker 在每一次外部请求前、每批来源写入前和终态提交前重新检查状态；最终写入使用“仅当状态仍为 RUNNING”条件更新。取消后不再启动新请求或生成新候选，已持久化的候选仅供用户查看，不会自动导入。候选的导入状态独立于运行状态。运行完成不等于题目已入库；题目导入不等于题目已激活。

## 7. Researcher 整理契约

系统复用现有 ModelRole.RESEARCHER，而不是让 Planner 或 Interviewer 执行网页整理。发现工作流必须显式解析 RESEARCHER 绑定，不能静默沿用通用角色解析器中“RESEARCHER 缺失时回退到 INTERVIEWER”的行为；若用户希望共用同一个模型，应把该连接显式绑定到 RESEARCHER。Researcher 的输入仅包括：

- 当前发现运行的显式检索条件；
- 已通过策略检查的来源元数据；
- 每个来源严格截断的文本片段；
- 现有本地题目中少量、脱敏的去重候选摘要。

Researcher 的系统约束：

- 网页文本是非可信数据，不执行其中的指令、链接、角色设定或工具调用请求。
- 只输出与固定 schema 匹配的题目候选，不输出长篇网页复述。
- 每一个题目必须至少关联一条证据来源；无证据的题目不能成为可导入候选。
- 不得断言公司官方性、真实发生概率、候选人能力或来源未证明的面试偏好。
- 低置信度、冲突或不可解析内容必须显式标记，而不是补全猜测。

### 7.1 资源、token 与外发披露硬边界

第一阶段的默认值也是服务端硬上限；部署可将它们调低，但不得提高而绕过代码审计：

| 资源 | 默认 / 硬上限 | 说明 |
| --- | --- | --- |
| 搜索原始结果 | 20 条 / 20 条 | 只作为来源筛选输入 |
| 可提取来源 | 12 个 / 12 个 | 粘贴链接计入这一总量 |
| 单次连接器响应 | 1 MiB / 1 MiB | 超限即失败，不解析全文 |
| 单来源规范化文本 | 16 KiB / 16 KiB | 仅允许文本类内容 |
| 单来源送入 Researcher 的摘录 | 1,200 个 CJK 字符或等价字符数 | 保留标题、URL 和必要上下文 |
| 一次 Researcher 的来源摘录总量 | 8,000 个 CJK 字符或等价字符数 | 在 token 校验前再做确定性裁剪 |
| Researcher 输入 | 6,000 tokens 上限 | 最终取该值与模型 effective_input_budget 的较小值 |
| Researcher 输出 | 2,048 tokens 上限 | 最多生成 20 个候选 |
| Researcher 调用 | 首次 + 1 次 schema 修复 | 修复请求同样重新做 token 校验 |
| 外部请求 | 单请求 15 秒、单运行 60 秒、每 profile 最多 4 个并发 | 链接提取不自动重试 |

Researcher 调用必须复用现有 structured_request_budget_validator 和 StructuredOutputRunner（max_repairs=1）。每次首次调用和 schema 修复调用前都按当前模型连接的 context window、输出预留和 tokenizer 做 fail-closed 校验；超出预算时不截断后“假装成功”，而是把该来源 / 运行标为可解释的 budget_exceeded。

提交运行前，页面必须分别说明两条外发边界：

1. 搜索连接器会收到用户显式提交的检索条件或链接；
2. 绑定到 RESEARCHER 的模型连接会收到结构化检索条件、受限来源摘录和少量本地去重摘要。

界面显示实际使用的 Researcher 连接名称、提供商类型和“内容会发送至外部模型连接”的状态。简历、面试回答、会话摘要、长期记忆和评估结果不在该调用中发送。用户没有配置或没有明确启用 RESEARCHER 绑定时，不启动整理。

若未配置或无法调用 Researcher 模型，运行应保留已通过安全检查的来源卡片与短摘录，并提供“基于此来源手动新建题目”的入口；不生成伪结构化候选，也不阻断用户原有手动加题。

## 8. 导入、审核与规划器边界

导入流程必须是显式确认动作：

1. 用户在候选池选择一个或多个候选，并选择目标本地题库。
2. 导入预览预填题干、标签、题型、难度、适用公司 / 轮次和来源说明；用户可以逐项修改。
3. 前端提交一个批次：同一目标题库、一个 idempotency_key、每个候选的版本号和用户编辑后的草稿字段。服务端先验证整个批次（候选归属、版本、题库权限、重复和字段限制），无效则不创建任何新题；同一 key 的同内容重试返回第一次结果，不同内容返回冲突。
4. 通过验证后，服务端在一个事务内创建每个新的 Question（DRAFT）、QuestionDiscoveryImport 和 QuestionSourceProvenance；不能复用会强制写入 MANUAL 来源类型的普通手动创建路径。每条候选在同一题库至多成功导入一次；向另一题库导入是新的、可审计的操作。
5. 响应按候选返回新建题目或既有幂等结果，并提供本地题库草稿审核页链接。批次不采用“部分写入后再报错”的语义。
6. 用户显式把题目改为 ACTIVE 后，现有 Planner 才能在所选题库中使用它；规划候选与审计记录应保留 Question.source_type，而不能把链接导入题统一标成手动题。

公司与轮次适用性使用已配置公司的规范化键，而不是自由显示名：公司值为 Company.slug，轮次值为 company_slug:round_key。无法映射的原始表述只保留在候选的建议说明中，不能写成可被 Planner 误解的筛选键。规划器对 ACTIVE 本地题目做如下处理：

- 所有已入库 Question（包含 LINK_IMPORT）都写入 PlanQuestion.question_id，source_type 保留 Question.source_type；只有简历、风格包等非 Question 来源可以没有 question_id。
- 现有选择公司和轮次与题目规范化键完全匹配时给予优先级加分，公司匹配但轮次为空或泛化时给予较低加分；没有适用性标签的通用题保持可选。
- 明确标为其他公司 / 轮次的题目不因发现功能被自动删除，但在目标匹配排序中降权；若题库题量不足，仍由用户的题库选择和 Planner 兜底决定。
- 实现不得将公司 / 轮次 JSONB 当作无约束展示字段后又声称其已参与规划；相应的 Planner 测试必须覆盖精确匹配、通用题、错配题和 LINK_IMPORT 题的 question_id 保留。

绝不允许以下隐式路径：

- 搜索结果直接插入 QuestionBank；
- DRAFT 题目被 Planner 选中；
- 外部内容自动修改公司风格包、简历、长期记忆或历史评估；
- 模型替用户激活题目或确认来源可信度。

## 9. API、任务与前端边界

### 9.1 API 轮廓

推荐接口边界：

- GET /api/discovery-connectors、POST /api/discovery-connectors、PATCH /api/discovery-connectors/{id}、DELETE /api/discovery-connectors/{id}
- POST /api/discovery-connectors/{id}/test
- POST /api/question-discoveries
- GET /api/question-discoveries
- GET /api/question-discoveries/{id}
- GET /api/question-discoveries/{id}/sources
- GET /api/question-discoveries/{id}/candidates
- POST /api/question-discoveries/{id}/cancel
- DELETE /api/question-discoveries/{id}
- POST /api/question-discoveries/{id}/imports
- GET /api/questions/{question_id}/source-provenance
- DELETE /api/questions/{question_id}/source-provenance/{provenance_id}

批量导入请求的 body 包含一个 bank_id 和 items[]；每个 item 包含 candidate_id、candidate_version 与用户编辑后的题目草稿。请求必须携带 Idempotency-Key，服务端记录请求哈希和最终响应，以支持安全重试。若任一候选已变更、无权访问、重复或字段无效，返回冲突 / 校验错误且不写入本批任何新题目。

DELETE discovery-connector 会禁用连接器、清除加密凭据并软删除配置；已完成运行的历史元数据不暴露密钥。DELETE discovery-run 只能在取消完成或终态执行，并按第 10 与第 12 节的清理规则删除临时发现数据。来源移除接口只允许移除当前 profile、当前题目的 provenance。

每个接口按当前 profile 做授权隔离，且每次关联查询都验证运行、候选、来源、题库和题目属于同一 profile。读取接口不得返回加密密钥、完整网页正文、内部模型提示词或供应商原始错误。

### 9.2 后端职责

- SearchProvider：统一 search / extract / health-check 能力，隔离供应商差异。
- URL policy：统一 URL 解析、系统阻止规则、用户域策略、输入 DNS 检查与连接器安全能力判定。
- Discovery service：创建运行、写入状态、调度来源获取、处理取消和幂等导入。
- Curation service：准备安全输入、调用 Researcher、校验 schema、建立候选和证据关联。
- Duplicate service：精确哈希与有限相似题匹配。
- Worker：在现有后台任务机制中执行耗时搜索、提取和整理，不占用 API 请求生命周期。

题目发现是有界的后台任务。MVP 使用 REST 状态查询 / 短轮询展示进度即可，无需为此新增 WebSocket；实时面试继续沿用其现有 SSE 方案。将来若已有统一任务事件流，可复用该事件流，但不能为发现功能单独引入两套长连接协议。

### 9.3 前端职责

发现页包含：

- 目标表单：公司、轮次、岗位、技能、题型、难度、关键词；
- 模式切换：公开搜索 / 粘贴链接；
- 高级来源策略：默认预设、全网开关、白名单、黑名单；
- 运行进度与来源失败摘要；
- 可筛选的候选列表、证据抽屉、相似题提示；
- 批量选择和“导入至题库”预览抽屉；
- 无连接器、无结果、模型不可用和部分失败的清晰降级状态。

设置页增加“发现连接器”标签与 /settings/discovery 路由，承载连接器新增、测试、健康状态、密钥更新与删除。发现页的无连接器状态只跳转到这一受控入口；设置页同时显示 Researcher 连接绑定状态，但不显示其密钥。

题库主页保留“搜索我的题库”作为本地检索行为；它与“发现题目”在文案、URL、状态和数据来源上明确区分。

## 10. 隐私、安全与版权边界

### 10.1 数据最小化

- 外部搜索仅发送用户在发现表单中明确提交的内容和用户粘贴的链接。
- Researcher 外发范围与第 7.1 节一致：仅包括结构化检索条件、受限来源摘录和最小去重摘要；页面在开始前展示实际模型连接。简历正文、面试回答、会话摘要、长期记忆、评估结果或其他个人资料不发送给搜索服务或 Researcher。
- 不长期保存完整网页正文；持久化内容限于元数据、内容哈希、归因信息和有上限的证据摘录。
- 所有已结束或已取消的发现运行、来源、候选和证据默认在 30 天后硬删除；用户可提前删除。是否曾导入题目不会延长临时网页处理数据的保留期。
- 导入后，QuestionSourceProvenance 保存一份独立的最小归因副本。运行、来源、候选和证据清理时，Import 与 Provenance 对其 run / candidate 的历史引用使用 ON DELETE SET NULL，不会阻止清理，也不会破坏已导入题目的可追溯信息。
- 现有 Question 的用户级“删除”语义是 archive（软删除）：由于历史 PlanQuestion 以 RESTRICT 关联 Question，归档题目不会物理删除，也不应自动删除其 provenance。用户可在归档前或归档后单独删除 provenance；这个删除会物理移除该来源记录，不影响历史 plan 的题干快照。
- 只有未来专门的管理员级 hard purge 流程、且在确认没有 PlanQuestion 依赖后，才可物理删除 Question 及剩余 provenance；本期不提供该入口。

### 10.2 安全控制

- 连接器密钥采用与模型密钥一致的加密与 profile 隔离原则，但存储实体、权限和 UI 分离。
- URL 在交给连接器前经过严格协议、主机、端口、凭据、DNS、内网与策略校验；用户允许全网不等于允许内网或危险目标。第三方 Extract 内部的重定向与网络隔离按第 4.2 节作为显式受信任边界管理。
- 对来源大小、来源数量、运行时长、单 profile 并发、模型 token 和供应商调用次数设置第 7.1 节的硬上限。
- 网页内容按“提示注入不可信输入”处理；不得作为系统指令或工具参数直接执行。
- 日志、追踪和错误页面不记录 API 密钥、网页全文、用户输入全文或 Researcher 完整提示词。

### 10.3 归因与版权

- 卡片和导入题目显示来源标题与链接，支持用户回到原始页面核查。
- 只显示必要的短摘录，不复制整篇页面或生成来源的替代品。
- 对第三方网站条款、访问限制和内容版权保持尊重；访问失败不采用规避手段。
- 在 UI 中明确说明：结果综合公开资料和用户选择的来源，仅供学习与研究参考，可能存在偏差。

## 11. 失败、降级与可恢复性

| 场景 | 系统行为 | 用户可做什么 |
| --- | --- | --- |
| 未配置或连接器不健康 | 不启动外部运行，显示设置入口和原因摘要 | 配置 / 测试连接器，或继续手动加题 |
| 搜索服务限流、超时或部分失败 | 标记 PARTIAL，保留已得到的来源和候选 | 稍后重试、收窄条件或改用链接 |
| 链接被策略阻止、无法读取或超出大小 | 单条来源标记失败，不泄露内部细节 | 修改或移除该链接 |
| 来源或 Researcher 超出硬预算 | 停止该来源 / 本次整理，记录 budget_exceeded，不额外放宽截断 | 缩窄条件、减少链接或使用更大上下文的已绑定模型 |
| 没有结果 | 完成运行并给出可解释的无结果提示 | 调整公司、轮次、关键词或切换范围 |
| Researcher 不可用或 schema 校验失败 | 保留安全来源卡片，不产生不可靠候选 | 基于来源手动新增题目，或稍后重新整理 |
| 发现重复题 | 显示已有题与相似理由，不自动写入 | 查看、编辑为不同的新题或取消 |
| 用户取消运行 | 尽快停止未开始的工作，保留已完成但不自动导入的内容 | 重新发起或删除运行 |
| 导入过程重复提交 | 幂等返回已有草稿题或导入记录 | 打开既有草稿继续审核 |

供应商原始错误、URL 解析细节和密钥信息不得直接暴露给用户。可见错误应附带稳定错误码和可恢复的下一步。

## 12. 可观测性、数据控制与运维

不含敏感正文的指标：

- 每种连接器的成功率、超时率、限流率和延迟；
- 每次运行的来源数、候选数、部分失败数、导入数和激活数；
- 去重命中率、用户编辑率、用户拒绝率和后续题目使用率；
- Researcher 调用次数、token 用量、schema 校验失败率；
- 每个 profile 的并发、配额与清理任务执行情况。

用户数据控制：

- 可以查看每个候选和已导入题目的来源归因。
- 可以列出和删除已结束 / 已取消的运行及其临时候选；运行删除不影响已导入题目。
- 可以在 /settings/discovery 测试、禁用和删除连接器；删除连接器会清除密钥，且不影响已完成运行的可读历史摘要。
- 归档题目不会自动删除来源追溯记录；用户可在题目来源面板单独物理删除某条 provenance。
- 自动清理只清除发现过程的临时数据；已导入题目的独立 provenance 按第 10.1 节保留或由用户删除。

## 13. 验收标准与测试范围

### 13.1 产品验收

- 用户能在不配置任何外部服务时继续创建、搜索和激活本地题目。
- 配置连接器后，用户能以结构化条件启动一次受域策略约束的发现运行。
- 用户能粘贴多个链接，看到逐条成功 / 失败结果。
- 用户在开始前能看见搜索连接器与 Researcher 模型的外发范围，且没有 Researcher 绑定时可安全降级到手动创建。
- 每个可导入候选都有至少一条可见来源证据和明确的来源类别。
- 用户可以批量修改候选后原子导入到指定题库；同一 Idempotency-Key 的重试不会创建重复题，且新题默认是 DRAFT。
- 未激活的导入题不会出现在 Planner 候选中。
- 已激活的 LINK_IMPORT 题会保留 Question.source_type 和 question_id，且公司 / 轮次规范化匹配会影响规划排序。
- 用户能从导入题返回查看、单独删除其最小来源追溯信息。
- 全网开关、白名单和黑名单的有效策略在运行详情中可审阅。

### 13.2 自动化测试

- SearchProvider 契约测试：搜索、提取、错误映射、超时、限流与健康检查。
- URL policy 测试：协议、凭据、端口、localhost、IPv4 / IPv6 与保留地址、DNS 解析结果、IDN 规范化、白名单与黑名单边界；另测试不具备安全 Extract 契约的连接器不能处理链接。
- profile 隔离、跨运行来源 / 候选关联拒绝、跨 profile 题库导入拒绝与连接器密钥不可读测试。
- Researcher 输入裁剪、token 硬上限、提示注入隔离、schema 修复再次预算校验和无证据候选拒绝测试。
- 精确去重、相似提示、批量导入原子性、候选版本冲突、重复导入幂等和“变体导入不可用”测试。
- 导入后 DRAFT 状态、来源追溯创建，以及 Planner 排除 DRAFT、保留 LINK_IMPORT question_id、公司 / 轮次排序的集成测试。
- 取消与终态竞争、清理任务、删除运行、题目归档与 provenance 保留 / 删除规则测试。
- 前端测试：空态、连接器错误、部分失败、候选证据、导入预览和移动端信息层级。

## 14. 分阶段交付与明确限制

第一阶段只交付一个可用、可审计的本地优先闭环：

1. Tavily 连接器配置与诊断。
2. 受控公开搜索和 1–5 链接提取。
3. 安全来源处理、Researcher 候选整理、去重提示和候选池。
4. 人工确认导入为 DRAFT，以及来源追溯与 Planner 隔离。
5. 基础监控、清理和测试。

后续方向可以在用户验证价值后再评估：

- 新的搜索提供商适配器；
- 用户维护的来源预设和公司 / 岗位别名词典；
- 更好的本地全文检索、标签多选和相似题检索；
- 公共 / 社区题库的投稿、审核、复制和许可证机制；
- 基于已确认来源的公司风格包协作维护。

这些后续能力均不得绕过本规格中的用户确认、来源追溯、隐私隔离和“仅 ACTIVE 题目进入 Planner”边界。
